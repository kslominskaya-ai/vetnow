# CLAUDE.md · правила для агента в проекте Vetnow

@AGENTS.md

## Продукт
Vetnow: срочная запись к ветеринару через SOS. Описание продукта в PRODUCT.md, визуальные правила в DESIGN.md, принятые решения в DECISIONS.md. Прочитай их в начале каждой сессии.

## Стек и версии
- Node 24 (см. .nvmrc)
- Next.js 16.4.6 (App Router), React 19.2, TypeScript 5.9
- Tailwind CSS 4, токены в app/globals.css через @theme
- базовые компоненты shadcn/ui в components/ui
- тесты: Vitest (tests/unit) и Playwright (tests/e2e)
- база Supabase подключается позже, сейчас только моковые данные

## Команды
- установка: npm ci
- запуск: npm run dev (http://localhost:3000)
- проверка типов: npm run typecheck
- юнит-тесты: npm test
- e2e-тесты: npm run test:e2e (перед запуском остановить npm run dev)
- сборка: npm run build

## Как работаем
1. Читаешь спецификацию задачи в docs/specs/.
2. Предлагаешь план: какие файлы создашь или изменишь, какие команды запустишь, как проверим результат.
3. Ничего не меняешь и не запускаешь, пока я не подтвержу план.
4. После выполнения показываешь список измененных файлов и результаты проверок.
5. Объясняешь простыми словами, что делает каждый новый файл: я дизайнер и учусь читать код.

## Коммиты
- Коммиты делаю я сама, ты только предлагаешь текст сообщения.
- Формат: feat: для новой фичи, fix: для исправления, docs: для документов, chore: для настроек. Вторая строка: «Зачем: ...».
- Одна фича = один коммит. В тот же коммит входят спецификация с планом и запись в DECISIONS.md.

## Чего нельзя
- Не устанавливать новые пакеты и не менять package.json и package-lock.json без моего одобрения.
- Не менять схему базы без миграции в supabase/migrations.
- Не читать, не создавать и не менять файлы .env*, не выводить ключи и пароли.
- Не делать git commit, git push и git revert самостоятельно.
- Не прописывать цвета, радиусы и размеры прямо в компонентах: только токены из app/globals.css.
- Не добавлять геолокацию, карты, оплату и пуш-уведомления: их нет в рамках курса.
- Не показывать владельцу телефоны и данные других владельцев; администратор клиники видит только запросы своей клиники.
